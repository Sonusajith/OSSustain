# Phase 5: snapshots and labels

## Frozen definition

Protocol `config/experiment.yaml` remains v1.0.0: theta 0.5, at least 20 reference
commits, 90-day reference and future windows, one prediction every 30 days.
Sensitivity at 0.3 and 0.7 is descriptive; the primary threshold is not selected
from test-period results. Features and models are outside this phase.

The schedule starts at observation_start + reference_window_days (2022-04-01),
then advances exactly 30 days through observation_end. It does not restart at
split boundaries or round to calendar months. All boundaries are midnight UTC.
Reference activity uses [tâˆ’90 days, t); future activity uses [t, t+90 days).
The last observation date is inclusive: 2025-12-31 means data are available up
to, but not including, 2026-01-01 00:00 UTC. A future window ending exactly there
is complete. Future counts are null if the entire future window is unavailable,
even if some events after t have already been collected.

Known bots are excluded. Unlinked authors remain included in commit activity
because their bot status is unknown, and their contributor identity stays null;
the report counts these events explicitly. This does not assert they are human.
Only default-branch history collected by Phase 3 is used. Timestamps use the
existing collector's `committed_at` field (author date, falling back to committer
date); mutable Git history and historical bot classification remain limitations.

Low reference activity is unlabeled, including zero reference commits. Label 1
means future activity <= theta Ã— reference activity; equality is inclusive.
Unlabeled records never enter prevalence denominators. A denominator of zero
produces null prevalence, not zero.

## Splits and completeness

Prediction-date split endpoints are inclusive. Dates in the configured gaps are
`purged`; dates outside the three windows are `unassigned`. Split membership and
label eligibility are separate: training/evaluation must filter both the desired
split and `label_status = 'labeled'`. Purged dates may have observable labels but
must not enter training or evaluation. Adjacent splits must be separated by at
least max(purge_gap_days, future_window_days). No future outcome is a feature.

The builder requires a matching Phase 4 quality report with all collaboration
stages complete and a completed commit checkpoint for every selected repository,
recorded after the observation period ends. Four Phase 4 quality flags are retained
without removing repositories. A stopped/failed commit refresh blocks the build.
Rerun `validate` after any collection refresh before building a new dataset.

## Storage and reproducibility

Flyway V6 adds `dataset_versions` and `snapshots`, matching the research entities
in Architecture.md. The earlier V3 `repo_windows` and `labels` are unversioned
dashboard/development-seed scaffolding and are not populated by this stage.
Phase 6 must read the versioned `snapshots` table; connecting the older prediction
scaffold to research models belongs to its later phase.

Each version records the experiment, cohort hash, exact snapshot implementation
hash, source commit-data hash, code revision, and summary. The version hash also
includes the quality-report hash. Source events include SHA, UTC timestamp, and
known/unknown bot state, only inside the observation period; identity secrets are
never included. Changed inputs or implementation create a separate version.
An unchanged rerun preserves the version, snapshot IDs, and original provenance.
Running from uncommitted snapshot code marks the revision `+dirty` and still
records its exact implementation hash; use committed code for final research runs.

All source reads and snapshot writes use one repeatable-read transaction. Failed
builds roll back rather than leaving a partial version; restarting repeats that
small derived-data stage. Conflicts never overwrite existing snapshot values.
The JSON report can be regenerated by rerunning the same command if writing the
file fails after the database commit. Detailed reports are ignored by Git.

## Acceptance results

Completed on 2026-11-18 against all 50 selected repositories. Dataset ID 1,
version `20186258c8680c150ec8834af87bff9b4e9c950efef22ee8f022c2f8b8dcccab`,
code revision `61ecefb111751b9d2cc9fe90313b2d2334a984c1`. The ignored detailed
report is `pipeline/data/reports/phase5-snapshots.json`; the same summary is
stored in `dataset_versions.summary`.

There are **2,300 snapshots**: 46 per repository, from 2022-04-01 to 2025-12-11.
Of these, 395 are labeled, 1,755 have insufficient reference activity, and 150
have incomplete futures. The 53 labeled snapshots in purge gaps are excluded
from modeling, leaving **342 eligible labeled snapshots** (164 train, 90
validation, 88 test). All 50 repositories remain in the dataset.

The observation period contains 18,630 stored commits: 4,028 known-bot commits
excluded and 521 unlinked-author commits retained in activity. These are
observation-period counts, not the 55,206 commits across full collected history.

All **59 Python tests passed**, including the live database idempotency test;
Ruff passed. All **8 backend tests passed**. Repeated builds preserved the same
version, IDs, counts, and labels. Independent SQL recomputed every snapshot's
counts and primary label: **zero mismatches**, and no incomplete labeled windows.
Flyway V6 applied to the local database; no collection or raw-data records changed.

The large low-activity fraction limits the size of the future modeling sample.
Overlapping windows and repeated repositories mean snapshots are not independent
observations. Keep the frozen parameters; do not tune thresholds using these test
period prevalences. Four Phase 4 quality flags remain attached to the summary.
Unit tests cover half-open UTC boundaries, incomplete futures, the minimum
reference count, inclusive thresholds, purge gaps, and exclusion of unlabeled
records from prevalence. Backend tests verify V6 and reject incomplete labels
and duplicate version/repository/date keys. The optional local-database test
checks repeatability, stable IDs, and absence of incomplete labeled windows.
