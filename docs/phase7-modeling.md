# Phase 7 modeling and temporal evaluation

## Evaluation protocol

The stage reads only snapshots whose `label_status` is `labeled`, whose label is
present, and whose split is `train`, `validation`, or `test`. Purged,
low-reference, incomplete-future, and unassigned rows are excluded. It never
reads `future_activity` as a predictor. The Phase 5 chronological dates and
90-day purge gaps remain unchanged.

All preprocessing is fitted on training data during tuning. Candidate
hyperparameters are ranked by validation average precision (reported as
PR-AUC); ties use lower validation Brier score, then a stable lexical parameter
ordering. For each selected algorithm and feature family, the probability
cutoff is chosen to maximize validation F1; tied cutoffs use the higher value.
The estimator is then refit on train plus validation, and test is evaluated
once using that frozen cutoff and parameter set. The highest validation PR-AUC
selects one model per feature family; Brier score and a fixed algorithm order
break exact ties. Test metrics never affect parameter, cutoff, or model
selection.

## Candidate models

The fixed recent-activity baseline assigns score `clamp(1 − 3 × commits_30d /
commits_90d, 0, 1)` and uses cutoff 0.5. This corresponds to recent monthly
activity at or below half the 90-day average monthly rate. The machine-learning
models are class-weighted or unweighted Logistic Regression (C from the frozen
grid), Random Forest, and Gradient Boosting. The activity-only family uses
`commits_30d`, `commits_90d`, and `commits_180d`; the extended family uses all
23 registered Phase 6 features. Undefined values are median-imputed using
training rows only. Logistic Regression also uses a scaler fitted on training
rows.

`config/modeling.yaml` freezes the seed, candidate grids, 2,000 repository
cluster bootstrap resamples, calibration bins, and permutation repeats. The
threshold baseline is repeated for both feature families to provide a
consistent comparison. `scikit-learn` and `joblib` are pinned in the pipeline
dependency files; artifacts are stored locally and are not committed.

## Reported results

The run writes PR-AUC, ROC-AUC, precision, recall, F1, and Brier score for
validation and test, overall and by repository size. It also stores sample and
class counts, decision cutoffs, equal-width calibration bins, and 95% percentile
confidence intervals from resampling repositories as clusters. Single-class strata have undefined
PR-AUC/ROC-AUC recorded as null. Logistic Regression reports standardized
coefficients; tree models report permutation importance on validation data.
The selected activity-only and extended models also receive a paired
repository-cluster bootstrap of test metric differences (extended minus
activity-only) on identical snapshots. Feature importance is predictive
association, not causal evidence.

The actual report and score tables are generated by `train`; results must be
interpreted with the small sample: 164 train, 90 validation, and 88 test labeled
snapshots from 50 repositories. Snapshots within a repository are correlated,
which is why confidence intervals resample repositories. Threshold 0.5 yields
different decline prevalences across periods (37.2% train, 45.6% validation,
27.3% test); comparisons must account for that shift. The final report should
include null or weak results as measured and must not be retuned against test.

## Recorded run: dataset 1

The frozen search selected Random Forest for activity-only (validation PR-AUC
0.647; validation cutoff 0.471) and Logistic Regression for extended features
(validation PR-AUC 0.628; cutoff 0.350). The test set contains 88 snapshots
(24 positive) from 12 repositories. The score for a random ranking would be
about the test prevalence, 0.273.

| Feature family | Algorithm | Validation PR-AUC | Test PR-AUC (95% repository CI) | Test ROC-AUC | Test Brier |
|---|---|---:|---:|---:|---:|
| Activity only | Threshold baseline | 0.557 | 0.353 (0.223–0.592) | 0.523 | 0.258 |
| Activity only | Logistic Regression | 0.607 | 0.401 (0.251–0.634) | 0.664 | 0.196 |
| Activity only | Random Forest (selected) | 0.647 | 0.272 (0.133–0.528) | 0.439 | 0.309 |
| Activity only | Gradient Boosting | 0.624 | 0.246 (0.129–0.532) | 0.439 | 0.275 |
| Extended | Threshold baseline | 0.557 | 0.353 (0.223–0.592) | 0.523 | 0.258 |
| Extended | Logistic Regression (selected) | 0.628 | 0.460 (0.232–0.709) | 0.658 | 0.245 |
| Extended | Random Forest | 0.567 | 0.236 (0.129–0.495) | 0.410 | 0.274 |
| Extended | Gradient Boosting | 0.610 | 0.278 (0.134–0.517) | 0.447 | 0.255 |

The paired repository bootstrap estimates the selected extended model's test
PR-AUC advantage over selected activity-only at 0.188, with a 95% interval of
−0.059 to 0.391. This interval includes zero, so the run does not establish a
reliable PR-AUC improvement from the extended feature set. Its Brier difference
is −0.064 (95% interval −0.172 to 0.015), also inconclusive. The 88-snapshot
test sample and 12 independent repository clusters limit precision.

By size group, selected-model test PR-AUC is 0.206 for activity-only versus
0.599 extended in large repositories (42 snapshots, 6 repositories); 0.442
versus 0.268 in medium repositories (30, 4); and 0.308 versus 0.685 in small
repositories (16, 2). These intervals are wide, especially for the two small
repository clusters, and are descriptive rather than a basis for separate
model selection.

All eight model-family/configuration records, 454 evaluation rows, and 78
importance rows are stored against dataset 1 in V8. The two validation-selected
model records are marked selected, and six joblib artifacts are stored locally
under the ignored `pipeline/artifacts/1/` directory. This is a baseline research
result, not a claim of robust predictive performance.
